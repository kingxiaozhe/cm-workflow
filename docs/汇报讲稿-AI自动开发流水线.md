## 一、开场（第 1 分钟）

【动作：投屏一页纸首屏，站定，不着急翻页】

各位好，今天占用大家十五分钟，汇报我最近搭建的一套 AI 自动开发流水线。

先用一句话说清楚它是什么：**需求文档丢进去，AI 自动拆成规格和任务清单，然后逐个开发、双重代码审查、动态触发测试、自动同步文档——全程状态落盘、可断点续跑、可审计。** 人在整个过程里只做两件事：**审需求规格、拍业务决策。**

今天我想讲清楚三件事：第一，它的 AI 实现机制是什么；第二，离投产还差什么、路径怎么走；第三，最后需要您拍板一个决策。

---

## 二、为什么做（第 2–3 分钟）

【动作：翻到 01 节，这一节快讲，不超过一分钟】

先说为什么做这件事。

直接让 AI 写代码，小需求没问题，项目一大就会以四种方式失控：上下文装不下全部需求、会话中断就前功尽弃、质量没人把关、需求一变容易把已完成的工作也推翻。

业界今年对这个问题已经有共识方向，叫**规格驱动开发**——AWS 的 Kiro、GitHub 的 Spec Kit、开源的 OpenSpec 都在这条赛道上。我做的这套，是这个方向上**执行管控更严**的一个实现：基于 Claude Code 的原生扩展机制，模块设计对齐 Google 发布的 Agent 设计模式，没有自研平台负担，官方能力升级我们直接跟着受益。

【动作：不停留，直接翻 02 节】

## 三、怎么工作（第 3–4 分钟）

【动作：指着三个流程卡片，从左到右】

整个流水线分三个阶段。

**阶段一，规格化。** 需求文档进来，AI 自动生成三份文件：需求、设计、任务清单，所有功能项、验收标准、任务都带编号，可追溯。这一步有个关键设计：**遇到歧义、遇到支付权限这类敏感点，它会强制停下来问人，绝不自行假设。** 人审完规格，才进入开发。

**阶段二，自动开发。** 按任务清单逐个执行，按任务类型自动派给十一个专业角色——产品、金融、前端、UI 还原、小程序、后端、数据库、合约、QA、运维、文档，每个 feature 以 staging 部署冒烟收尾。每个任务要过两道审查门禁才算完成，并且按风险评分动态触发测试。

**阶段三，收尾。** 自动同步 README、项目规范、变更日志，并做文档和代码的一致性校验。

## 四、AI 实现的六个关键机制（第 4–8 分钟，主战场）

【动作：翻到 03 节。这一节讲最慢、最稳。句式统一："大模型有个已知弱点 → 我用什么机制对付它"】

这一节是今天的重点。这套方案和"让 AI 放开跑"的本质区别，是下面六个机制——**每一个都针对大模型的一个已知弱点。**

**第一，状态外置，对抗上下文限制。** 所有状态都落磁盘：规格三件套、任务清单的勾选状态、经验库、git 提交历史。AI 的记忆随时可以清空、随时可以重建。这带来两个东西：一是断点恢复——会话断了、容器重启了，重跑就能从断点继续；二是**天然的审计链——任何一行代码都能回溯到对应的任务编号和需求编号。** 投产场景下，这条审计链是我认为最有价值的特性。

**第二，上下文轮换，对抗长会话漂移。** 大模型连续工作久了会注意力退化、偏离需求。所以每完成一个任务，就清空上下文、重新加载规格——**AI 永远以"新鲜大脑加完整规格"的状态干下一个任务。** 这是拿算力成本换可靠性，是这套方案最贵、也最值的取舍。

**第三，双模型交叉审查，对抗单模型盲区。** 执行模型先自审，然后第二个模型独立复审这个任务的代码变更——审查面小，两个模型互相挑错，审查不通过不允许标记完成。这里有个细节想特别说一下：**复审设了两轮硬上限。** 因为 AI 互相审查是没有尽头的，业界有真实案例，代码被无限改写到不可维护。超过两轮还有分歧，就留痕分流：涉及安全的升级人工，纯风格的放行。

【动作：如果老板对这条表现出兴趣或怀疑，切到编辑器展示 N4-review.md，说："这条规则是写死在流程文件里的，不是靠 AI 自觉。"然后切回来】

**第四，纪律与技术分层，对抗并行失控。** 并行的任务由预定义的子代理执行。子代理只管纪律：只做指定编号的任务、不碰边界外的文件、不自行标记完成、按固定格式汇报；技术规范由另一层技能文件提供。**两层分离，并行开得再多也不会互相踩踏。**

**第五，人机决策边界，对抗越权风险。** 写死在流程里：技术选型 AI 自主决定，不打扰人；但**业务歧义、破坏性数据库变更、合约上线、支付认证权限逻辑，强制暂停等人确认。** 每类子代理还有领域硬闸，比如数据库代理遇到删表必须上报，合约代理绝不接触私钥。

**第六，动态 QA 加量化验收，对抗测试成本和主观验收。** 测试不按固定间隔跑，按四维风险评分触发——改个文案不跑全量测试，动支付逻辑必测。UI 还原不靠"看着像"，用像素级对比工具量化差异。

## 五、投产路径（第 9–11 分钟）

【动作：翻到 04 节，先念"当前状态"那一行——主动交底，不等他问】

先交底当前状态：**这套流水线已经在一个真实小程序项目上完整跑过——12 个 feature、81 个任务，从 MVP 一路做到提审就绪。数据是：一次通过率 93%，AI 审查拦截 93 条问题、其中 4 条是上线必炸的 P0 级，81 个任务里计划外的人工介入是 0 次。之后又在同一项目上做了存量二开实测，184 个存量测试用例前后全绿，老功能零回归。** 唯一还没拿到的数字是单任务成本——这是接下来试点的第一指标。

投产我规划了三个阶段，**每个阶段有量化门槛，未达标不进下一阶段：**

**第一阶段，试点，下周。** 挑一个低风险小需求，三到五个任务，全流程走通，全程记录数据。门槛：流程无人值守跑通、人工介入每任务不超过两次（业务确认除外）、拿到实测单任务成本。

**第二阶段，灰度，试点后两到三周。** 两到三个真实需求，覆盖不同类型——纯前端、前后端联动、含数据库变更。门槛：任务一次通过率不低于百分之八十、上线后严重缺陷逃逸为零、单任务成本低于对应人工工时。

**第三阶段，投产。** 纳入正式研发流程：规格评审并入现有需求评审，产出并入现有代码评审和提测环节。

距投产的已知缺口，我列了四条，每条都有对策——单任务成本未实测（试点第一指标，采集机制已内置）、任务标记单点（已有回读校验，灰度加 git hook 双保险）、外部审查模型依赖（降级逻辑已实现且实测有效）、规格质量依赖人审（制度上设为强制环节，且机器项已由自检环节先行清零）。

最后说一个架构判断。**更强的 JS 编排引擎我已经评估过，升级点也锁定了，但我不会在拿到试点失败数据之前加架构。** 试点里"人工介入"这个指标，顺便就是升级决策的依据：介入都发生在业务确认上，说明现有引擎够用；发生在流程失守上，我才把对应节点代码化。**引擎升级看失败数据，不看技术潮流。**

# 附录一：备询应答（被问到时照此口径回答）

**问：成本多少？**
答：主要开销两块——每个任务重新加载规格（这是可靠性的代价）加双模型审查。比对话式开发贵，换来的是无人值守和质量门禁。确切数字是试点的第一指标，灰度门槛里我写了：单任务成本必须低于对应人工工时，否则不推广。

**问：AI 写的代码能信吗？**
答：三道防线：双模型交叉审查、风险评分触发 QA、高危操作强制人工确认。而且审查只看单个任务的变更，审查面可控。审查不通过，任务关不掉。

**问：AI 产出怎么审计？**
答：全程落盘——规格三件套、带编号的任务清单、每个任务的审查记录、经验库、git 提交历史，形成完整证据链。**任何一行代码都能回溯到对应任务和需求编号。**

**问：和直接用 Cursor / Copilot 有什么区别？**
答：那些是"人驾驶、AI 辅助"，效率上限受人的带宽限制；这套是"AI 执行、人把关"，把人的投入集中到规格和决策两个杠杆点，过程可以无人值守。

**问：市面上已经有 OpenSpec 这类开源方案，为什么自己做？**
答：方向一致恰好说明我们选对了——OpenSpec 和我们独立收敛到同一套规格三件套地基，连命令结构都一一对应。差别在覆盖面：OpenSpec 自己划的边界是"规划加实现"就停，明确不含代码审查、QA、部署发布、角色分工；而这四样正是我们面向"可投产"多做的。用一句话概括，OpenSpec 相当于我们流水线的前三个节点，我们把它一路延伸到了上线。它成熟的 CLI 工程化和跨团队协作是我们后续演进的现成参照，不是重复造轮子。

**问：需求中途变更怎么办？**
答：有专门的变更模式：新旧需求自动对比，任务清单增量更新——新增、修改、作废分别标记，**已完成的工作不推翻**，重跑自动跳过。

**问：为什么不直接上更强的多 agent 或 JS 编排引擎？**
答：都评估过，接口也预留了——多 agent 组队能力已经接入但默认关闭，JS 引擎的升级点已经锁定。原则是不在拿到试点失败数据前加架构，避免为技术而技术。

**问：AI 互相审查会不会失控？**
答：会，这是业界已知的失败模式，代码会被无限改写到不可维护。所以我设了两轮硬上限，超限分歧留痕：安全类升级人工，风格类放行。

**问：最大的风险是什么？**
答：规格错了，它只会更快地做错。所以"人审规格"是制度上的强制环节，不可省略。其次是任务标记单点，已有回读校验，灰度阶段再加 git hook 双保险。

# 附录三：三句话禁语

1. 不说"全自动开发" → 说"**AI 执行、人把关**"
2. 不说"能替代几个人" → 说"**把工程师的投入集中到规格和决策两个杠杆点**"
3. 效果数字只说实测过的 → **可说：81 任务 / 93% 一次通过 / 93 条拦截 / 存量回归 0 / 三阶段门槛**；不可说：成本与效率倍数（未实测）
