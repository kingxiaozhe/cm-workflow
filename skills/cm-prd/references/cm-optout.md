# $cm-prd 项目规则禁用 CM 时的确认

> 新建与变更模式在外部专家路由、调用 `cm-prd-entry.mjs` 准入、启动 JS 宿主之前执行本文件（实跑教训：aihot 的
> AGENTS.md 先后写过「只用 CM」和「不用 CM」，流程没有规定怎么处理）。本步只读，不读需求正文。

1. 以代码项目根（Step 3 的判定，不是当前会话所在仓库）为准，读其 AGENTS.md 链、根目录 `CLAUDE.md`、`.claude/CLAUDE.md`
   和 `.claude/rules/` 下全部文件（本步不按相关性筛选），只找不用 CM 工作流的条款；没有 → 照常继续准入。
2. 按规则自身声明的优先级（如「本节优先」「已被覆盖」）判断该条款是否仍生效；已被后续条款明确覆盖 → 照常继续。
3. 仍生效、无法判断，或条款只限某类需求而本步不读正文无法确定是否适用 → 在对话里问用户一次，问题里引用条款的文件与行号，等真实答复；不调用准入。
4. 用户明确同意运行 cm-prd，或说明本次需求不在条款限定范围内 → 继续准入；
   其余回复 → 不启动准入与宿主、不写 specs，说明原因后结束。
